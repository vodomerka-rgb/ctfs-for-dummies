# How messages converted into integers for cryptography
## Character Encoding:
First, characters are converted into bytes. Each character is represented by a sequence of bits in an encoding scheme like UTF-8 or ASCII. These are basically just ginormous dictionary tables that say the character “a” is “01100001”, “b” is “01100010” and etc. So, your entire message is first converted into a sequence of byes.

## Integer Conversion:
Now, as you may have noticed, algorithms like RSA do operations on 1 very large number, not a series of bytes, so we need to convert the byte array to an integer. However, if a cryptographic algorithm is using padding, an algorithm like EME-OAEP adds padding to the byte array before it is converted to an integer. 

The next part is to convert those bytes to a number, using an operation called Octet String to Integer Primitive or OS2IP. The formula for it is:

 $$m = \sum_{i=1}^{k} byte_i \cdot 256^{k-i}$$

Where k is the total number of bytes in the message and “byte” stands for the value of each byte. 

Let’s convert “OS2IP” because it’s easier to understand what is going on with an example.
First, convert it to a byte array with ASCII, so we have [01001111, 01010011, 00110010, 01001001, 01010000] which is [79, 83, 50, 73, 80 ] using decimal.
We won’t pad this so the array will be converted to an integer as is.
Using the formula for OS2IP, this would look like:
$$ m = 79 \cdot 256^{4} + 83 \cdot 256^{3} + 50 \cdot 256^{2} + 73 \cdot 256 + 80$$
So then, $$m = 340,698,220,880$$.

That integer would then be used to perform calculations in encryption.
